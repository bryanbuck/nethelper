
  Enhanced Debug Logging Features

  Connection Attempt Tracking

  - Logs OAuth2 connection attempts with URL and credentials info
  - Tracks API request initiation with method, endpoint, and parameters
  - Assigns unique request IDs for tracking individual requests

  Token Management Logging

  - Cache hits: "Using cached Aruba Central access token"
  - Cache misses: "No cached token found, requesting new access token"
  - Token caching: Logs cache expiry time and token length

  Request/Response Monitoring

  - Request details: Method, URL, payload presence, customer ID
  - Response timing: Measures and logs response time in milliseconds
  - Response analysis: Status codes, data size, array lengths, object keys
  - Success confirmation: Summary log for completed requests

  Error Diagnosis

  - HTTP errors: Status codes, response data, detailed error context
  - Network errors: Connection failures, timeouts, DNS issues
  - Request setup errors: Configuration or parameter problems
  - Error categorization: Distinguishes between network, HTTP, and setup errors

  Debug Information Includes

  - Request/response timing (responseTime: "150ms")
  - Data payload sizes and structure analysis
  - Token cache management (hits/misses/expiry)
  - HTTP status codes and response metadata
  - Unique request IDs for correlation ([abc123def])

  Usage

  Set LOG_LEVEL=debug in your .env file to see all debug output. The logging will show:

  1. Connection attempts to https://apigw-prod2.central.arubanetworks.com
  2. Authentication success/failure with timing
  3. API request/response details with data analysis
  4. Error diagnosis with specific failure reasons


  New Features

  Service-Specific Logging (src/utils/debug-logger.js):
  - 11 predefined service categories: AUTH, ARUBA_CENTRAL, DEVICE, AUTOMATION, NOTIFICATION, DATABASE, WEBSOCKET, API, MIDDLEWARE, JOBS, REDIS
  - Individual log level control: Set different log levels per service
  - Service filtering: Enable/disable logging for specific services
  - Request ID tracking: Correlate logs across service calls
  - Emoji prefixes: Easy visual identification (🔄 progress, ✅ success, ❌ error, ⚠️ warn, ℹ️ info, 🔍 debug)

  Configuration Options (.env)

  # Global log level
  LOG_LEVEL=debug

  # Service-specific levels (optional) 
  SERVICE_LOG_LEVELS=ARUBA_CENTRAL:debug,AUTH:warn,DEVICE:info

  # Enable specific services only (optional)
  DEBUG_SERVICES=ARUBA_CENTRAL,AUTH,DEVICE

  Usage Examples

  Service-specific logger:
  const { debugLog, Services } = require('../utils/debug-logger');
  const logger = debugLog.createLogger(Services.ARUBA_CENTRAL);

  logger.progress('Connecting to API');
  logger.success('Connected', { responseTime: '150ms' });
  logger.error('Connection failed', { error: err.message });

  With request tracking:
  const requestId = 'req_123abc';
  logger.debug('Processing request', { method: 'POST' }, requestId);
